# 开发日志 v1.1.0（2026-08-06）

## 版本概述
在 PDF 书籍处理阶段新增**版面分析与插图原位置插入**能力。处理后的章节 Markdown 不再在文末堆砌图片链接，而是把插图、图表、照片按在页面中的实际位置嵌入到正文里。

## 新增功能

### 1. Python 版面分析脚本
- **文件**：`src/main/python/pdf_layout_analyzer.py`
- **功能**：
  - 接收章节页面图片路径列表
  - 调用远程 OpenAI 兼容接口的多模态模型（默认千问 9b）
  - 识别页面中的文字与插图区域（返回相对坐标 bbox）
  - 按 bbox 裁剪插图并保存到 `output_dir/figures/`
  - 将 `[FIGURE:N]` 占位符替换为 Markdown 图片链接，按原位置插入
- **依赖**：`Pillow`、`openai`，详见 `src/main/python/requirements.txt`

### 2. Java 调用服务
- **文件**：`src/main/java/com/ocr/app/service/PdfLayoutAnalyzerService.java`
- **功能**：
  - 自动检测 Python 可执行文件（`python3` / `python` / `py`）
  - 构造命令行参数调用 `pdf_layout_analyzer.py`
  - 异步读取 stdout，设置进程超时（每张图片约 60 秒）
  - 将 Python 输出的 Markdown 返回给书籍处理服务

### 3. 书籍处理流程接入
- **文件**：`src/main/java/com/ocr/app/service/PdfBookAnalysisService.java`
- **改动**：
  - 章节处理时优先调用 Python 版面分析
  - 成功则使用带插图链接的 Markdown 作为章节原文
  - 失败时自动降级为原来的 OCR 文字提取逻辑
  - 使用版面分析时，不再在文末追加“本章图片”和“嵌入图片”列表

### 4. 配置开关
- **文件**：`config.json`
- **新增配置项**：`pdf.layout.analyzer.enabled`
  - 默认值：`true`（开启）
  - 设为 `false` 可恢复到原来的纯 OCR 模式

### 5. 配置服务增强
- **文件**：`src/main/java/com/ocr/app/service/ConfigService.java`
- **新增方法**：
  - `getConfigFilePath()`：暴露配置文件路径
  - `getConfig(String key)`：通用读取配置
  - `setConfig(String key, String value)`：通用写入配置

## 阶段隔离说明
- **书籍处理阶段**（`PdfBookAnalysisService.analyzeBook`）：执行插图提取与原位置插入
- **考试大纲解析阶段**（`ExamOutlineService`）：仅提取 PDF 文本，不处理图片
- **题目生成阶段**（`TaskQueueService`）：读取已生成的 Markdown 原文，生成题目，不添加图片也不抠图

## 测试建议
1. 确保 Web 服务器已安装 Python 依赖：
   ```bash
   pip install -r src/main/python/requirements.txt
   ```
2. 上传一本包含插图的 PDF 书籍
3. 检查生成的 `书籍第X章_原文.md`：
   - 插图是否出现在正文中对应位置
   - 文末是否不再有一堆图片链接
   - `figures/` 目录下是否有裁剪出的插图文件
4. 如需关闭该功能，修改 `config.json`：
   ```json
   "pdf.layout.analyzer.enabled": "false"
   ```

## 已知限制
- Python 脚本需运行在 Web 服务器本地，依赖本地 Python 环境
- 插图识别质量取决于远程多模态模型的能力
- 若模型未返回有效 bbox，对应占位符会被清空
